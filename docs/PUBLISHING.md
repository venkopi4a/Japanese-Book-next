# Publishing (GitHub website only)

The app publishes itself. Whenever the `main` branch changes, `.github/workflows/deploy.yml` installs, type-checks, runs the 78 tests,
builds with the right base path and deploys to GitHub Pages. If a test fails, nothing is published.
Live address: https://venkopi4a.github.io/Japanese-Book-next/

## One-time setup
1. Repository `Japanese-Book-next` -> Settings -> Pages -> Build and deployment -> Source: **GitHub Actions**.
2. Settings -> Actions -> General: Actions must be allowed (default).
3. Remove the old hand-uploaded build files from the repository root (index.html, sw.js, manifest.webmanifest, the index-*.js / index-*.css files, icon-*.png, favicon-32.png, art-banner.jpg). The source lives in `src/` and `public/`; the build output is generated by the workflow.

## Normal flow
Claude Code pushes a branch -> you open the pull request in the browser -> the "Check" run goes green -> Merge -> the "Publish" run deploys (about 1 to 2 minutes, see the Actions tab).

## If something fails
Actions tab -> open the red run -> the failing step shows the reason. Paste that text to Claude Code.

## iPhone note
After a deploy, open the installed app twice: the first open fetches the update, the "Reload" prompt appears, tap it. Settings should then show the new version.
